# Decisions

| # | Date | Decision | Why |
|---|---|---|---|
| D1 | 19 Nov 2026 | iOS + Android from day 1; iOS ready and tested (simulator + Maestro), App Store publish decided later | Owner request |
| D2 | 19 Nov 2026 | Rules-first AI planner; Worker /ai routes with AI_PROVIDER=none by default | Bible conflict: "no LLM costs" vs "LLM via Worker"; rules engine satisfies both |
| D3 | 19 Nov 2026 | Store subscriptions via react-native-iap (StoreKit 2 + Play Billing), verified by the Worker | Store policy for digital subscriptions; bible sheet 16 |
| D4 | 19 Nov 2026 | server: Cloudflare Worker (Hono) + MongoDB Atlas behind one `Db` interface (`MemoryDb` for tests). Tests run in Node with vitest + `app.request()`, not the miniflare pool | Portable backend; keeps dependencies to hono, jose, mongodb, wrangler, typescript, vitest (disk limit) |
| D5 | 19 Nov 2026 | server: sync pull pages by server write time (`syncedAt`) with an opaque cursor and a 2 s `nextSince` overlap; last-write-wins stays on client `updated_at`; Mongo `_id` = `userId:id`; rows are plain values with a field allow-list (`server/src/sync/tables.ts`) | Phone clocks are wrong often; cross-user id collisions become impossible; NoSQL operator injection is blocked |
| D6 | 19 Nov 2026 | server: `POST /auth/anonymous` creates the silent account from sheet 15 (AI + purchases before sign-in). Anonymous accounts cannot sync (403). Signing in upgrades the anonymous account in place, or merges its purchases into the existing account | Sheet 15 (no sign-up wall, anonymous data merges); sync stays backup-for-signed-in-users only |
| D7 | 19 Nov 2026 | server: a purchase belongs to the account that last verified it (restore moves it); StoreKit `appAccountToken` / Play `obfuscatedAccountId` only bind purchases first seen by a webhook. Store state is always re-read (Play API, Apple signed data); client claims are ignored | Cross-platform restore (sheet 16) without trusting the client |
| D8 | 19 Nov 2026 | server: App Store JWS verified with our own small DER/X.509 reader + Web Crypto, chained to the root pinned in `APPLE_ROOT_CA_G3_B64` (fail closed); Play RTDN accepts a Google OIDC token (preferred) or a `?token=` shared secret, fail closed when neither is set | Works in Workers without node:crypto X509; no extra libraries |
| D9 | 19 Nov 2026 | server: Anthropic AI v1, $50/mo cap. `AI_PROVIDER=anthropic` by default (overrides D2's `none` default): Claude Haiku 5.5 via the Messages API over fetch, JSON-schema output, cached system prompt, IDs-only prompts, 8 s timeout → rules fallback. Budget guard per calendar month: ≥80% free users rules-only, ≥100% everyone. Per-user daily limits (free < Pro), result cache by request hash, spend at `GET /ai/usage` (admin token) | Owner decision relayed by the orchestrator; ≈ $0.02 per typical active user per month, so $50 covers ~2,000 active users |
| D10 | 19 Nov 2026 | server: access JWT HS256 15 min (iss/aud checked); refresh tokens 60 days, sha256-stored, rotated, reuse revokes the family; every authed request looks the user up so tokens from before account deletion fail | Sheet 15 + account deletion requirement (sheet 24) |
